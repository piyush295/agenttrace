==================== COMMENT (ye paste karo) ====================

Author here.

Investigating AI-agent incidents turned out to be very different from traditional DFIR, which is why I built this:

- The attack vector is natural language - a malicious prompt looks identical to a legitimate one in almost every log teams collect.
- The anomaly is the sequence, not any single event. Each tool call is individually authorized and looks normal; the attack is the order they happen in.
- The evidence is spread across 6-7 systems (LLM invocation logs, tool traces, MCP servers, vector-store retrieval logs, OAuth records, egress logs), each with different owners and retention.

Recording agent activity is largely solved (OpenTelemetry GenAI, MCP logging, tamper-evident audit logs). Reconstructing what actually happened from that evidence is not - that's the gap AgentTrace fills.

It ingests those sources into one schema, verifies integrity + chain of custody (hash chains, signed manifests, a tamper-evident custody ledger), reconstructs the causal attack chain, and detects 6 patterns (prompt injection via retrieval, exfiltration via tool chaining, credential-theft chains, sub-agent hijack, memory poisoning, tool-permission escalation) - each mapped to MITRE ATLAS and linked to the exact evidence.

Two deliberate choices: no AI/ML in the detection path (everything is deterministic and explainable - important for something meant to hold up in a review or court), and zero dependencies so it runs fully offline / air-gapped.

Happy to answer questions, and genuinely interested in feedback on the detection heuristics and which additional evidence sources are worth supporting next.
